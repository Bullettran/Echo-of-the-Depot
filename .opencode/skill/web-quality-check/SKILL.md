# Чек-лист качества (веб-трек EchoOfTheDepot)

## Границы работы
- Кодер здесь — агент (пользователь ревьюит как фронтендер). Перед большим блоком — перечислить план и границы («пишу X и Y, Z не трогаю»).
- Диагностика без согласия разрешена всегда; правки — по задаче/просьбе.

## Команды-гейты (все обязаны быть зелёные)
1. `npm run typecheck` (tsc --noEmit) — 0 ошибок.
2. `npm run lint` — 0 ошибок/варнингов.
3. `npm run test` (vitest run) — 0 падений; новая логика в чистых системах = новые тесты.
4. `npm run build` — собирается.
5. Деплой-ссылка живая (если пушали в main).

## Архитектура
- [ ] Player худой: спрайт+движение+input; игровая логика — в компонентах/системах.
- [ ] Системы/компоненты не импортируют класс Player — только owner-интерфейс и EventBus.
- [ ] UI — только подписки на EventBus; мир не читает DOM; мост в `src/bridge/`.
- [ ] Данные (предметы/рецепты/реплики/модули) — в `src/data/*.json`, не в коде.
- [ ] Одна ответственность на систему/модуль; описание с «и» — делить.
- [ ] Меняли публичный API системы — grep референсов и обновить вызывающих.

## Гигиена кода
- [ ] Нет мёртвого кода, закомментированных блоков, `console.log` (временный — с пометкой `// TODO: remove`).
- [ ] Каждая функция/класс имеет JSDoc на русском (правило 8); публичный API отражён в `Docs/CODE_GUIDE.md`.
- [ ] Класс ≈ до 300 строк; функция — на один экран.
- [ ] Нейминг: классы PascalCase, члены camelCase, файлы kebab-case; булевы Is/Has/Can; события `On*`; инстансы EventBus-каналов — `domain:eventName`.
- [ ] Нет `any`; типы из `src/data/types.ts` переиспользуются, не дублируются.

## Runtime (гейты её не заменяют)
Инструмент — `playwright-cli` (скил `playwright-cli` в .opencode/skill; хук игры: `window.__eotd.player`, dev-only):
1. `playwright-cli.cmd open http://localhost:5173` (dev-сервер поднят как фоновая job).
2. Прогнать основное действие механики: `keydown/keyup`, `eval` позиции/состояния, `click` по DOM-панелям.
3. `playwright-cli.cmd console error` — 0 ошибок (warnings объяснить каждый).
4. `playwright-cli.cmd screenshot --filename=...` — приложить к отчёту при UI-работе.
5. Смоук «игрок ходит»: eval `__eotd.player.x/y` до и после keydown d — координата изменилась.

## Критик-вопросы (к каждой задаче)
- Что из этого можно удалить, и ничего не сломается?
- Что уже есть в другом модуле и переиспользуется?
- Влезает ли в вертикальный срез текущей W-фазы (Docs/WEB_PLAN.md)?

## Отчёт (обязателен)
1. **Оценка 0–10 с расшифровкой:** за что начислено (факты: тесты, гейты, чистота), за что снято.
2. Оценка словами — конкретно по фактам, не сухое «ок».
3. Поддержка: пользователь — сильный фронтендер, учится геймдеву; отмечать прогресс в игровых паттернах, критику — только с путём решения.
4. Что проверить руками пользователю + следующий шаг.
