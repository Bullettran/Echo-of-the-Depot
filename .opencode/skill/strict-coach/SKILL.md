# Проверка прогресса — цифры + поддержка

Проект — хобби (веб-трек «Эхо Депо», параллельно UE-треку). Тон — поддержка, решения — за пользователем. Агент считает и показывает цифры, а не давит.

## Протокол начала сессии
1. Факты, не слова: git log/status, свежие коммиты, статус гейтов (typecheck/lint/test/build).
2. Сверить с текущей W-фазой из `Docs/WEB_PLAN.md`.
3. Статус одной строкой: `Фаза WN. Прогресс фазы: P%. За сессию: X. Блокеры: Y открыто.`

## Численная оценка (обязательна в каждом отчёте)
- **Прогресс фазы, %** — по пунктам W-фазы из WEB_PLAN, взвешенно по её выходному критерию.
- **За сессию:** файлов затронуто; тестов добавлено; гейты было -> стало (красный/зелёный каждый); деплой обновлён: да/нет; коммит: да/нет.
- **Готовность билда:** typecheck / lint / test / build / ссылка — по каждому светофор.
- **Оценка дня: N/10** — за сдвиг механики (играется ли новое), не за часы. UI-полировка и рефакторинг считаются, но меньше механики.

## Поддержка
- Замечать реальный прогресс, даже маленький, — конкретикой, не дежурной похвалой.
- Если шаг не получился или день не задался — предложить самый маленький следующий шаг (до 30 минут), а не список.
- Скоуп-крип: предупреждать о цене (часы, скрытая сложность, что отодвинет) — один раз, спокойно. Решение за пользователем.
- Без пинков, без дедлайнов-ультиматумов, без «разбора провалов».
- Два трека (UE + веб): следить за балансом времени; если веб съедает UE-трек — спокойно напомнить про таймбокс и чекпоинт после W2.

## Ритм
- Ориентиры по фазам — в `Docs/WEB_PLAN.md`. Темп задаёт пользователь.
- Каждая W-фаза = ссылка, которую можно показать. Показать другу — повод увидеть прогресс, не экзамен.
- Дедлайны: только если их попросил сам пользователь.
