# WEB_PLAN — «Эхо Депо» в браузере (параллельный трек к UE)

> Цель трека: **проверить гипотезу** «фронтенд-разработчик + ИИ + браузер = играбельная игра с моим дизайном за недели, а не месяцы».
> UE-трек — основной. Веб-трек — эксперимент с точкой решения после вертикального среза (W2).

---

## 1. Рамки эксперимента

**Что проверяем:**
1. Скорость: вертикальный срез (петля «собери → скрафти → почини станцию») ≤ 3 недель по вечерам.
2. Качество процесса: комфортно ли делать игру с ИИ в вебе (файлы+тесты) против MCP-боли в UE.
3. Играбельность: понимают ли друзья игру без слов (критерий из Ф2 UE-плана).

**Точка решения (после W2):** продолжать веб-трек / заморозить и вернуть фокус в UE. Решает автор.

**Таймбокс:** например, 2 вечера в неделю + часть выходных. Если веб начнёт съедать время UE-трека — это сигнал к паузе трека, не к бросанию обоих.

**Формат игры:** 2D top-down survival, пиксель-арт, сессия 15–30 минут, играется по ссылке (десктоп; мобайл — stretch).

---

## 2. Что берём из UE-дизайна, что нет

### Берём как есть (дизайн движок-независим)
- Весь LORE: мир, АРХИВ, станция-узел, допуски ЖД, «связность» как метрика прогресса.
- Игровая петля: нужды → ресурсы → крафт → ремонт модулей → оборона → переезд-глава.
- Все константы дизайна: день = 10 минут, волны каждые 3–6 дней, 3 ключевых модуля (реактор → ворота → вышка), смерть = статы 50% + дебафф «Перезагрузка носителя», лут только материалы.

### Переносим с заменой носителя
| UE | Web |
|---|---|
| `BPC_*` ActorComponents | TS-классы-компоненты на сущностях |
| Event Dispatchers | типизированный `EventBus` (pub-sub) |
| `DT_Items / DT_Recipes / DT_Effects` | JSON + TS-типы (`src/data/`) |
| `S_* / E_*` структуры и енумы | TS `interface` / `enum` (PascalCase сохраняем) |
| Behavior Trees (2 врага) | конечные автоматы (FSM) на enum + таблица переходов |
| UMG-виджеты | **DOM/CSS поверх canvas** — наша суперсила |
| BP_Save | `localStorage` (JSON), позже IndexedDB |
| Niagara/3D-свет | спрайты, CSS-глитчи, свет = маска-затемнение |

### Не берём
- 3D, первое лицо, сложные VFX — в браузере сознательно не пытаемся.
- Blueprint-ассеты PhaseLands — не переносимы, логику переписываем по спеке (она задокументирована).
- Полную копию UE-плана фаз: веб-фазы сжаты (см. §7).

## 3. Стек и что понадобится

### Стек (обоснование — минимум лишнего, максимум знакомого)
| Слой | Выбор | Почему |
|---|---|---|
| Язык | **TypeScript (strict)** | guardrail для ИИ: типы ловят галлюцинации агента |
| Сборка | **Vite** | HMR, нулевой конфиг, деплой = статика |
| Движок | **Phaser 3** (стабильная ветка) | сцены, спрайты, arcade-физика, tilemap, камера, твины — всё из коробки |
| UI | **DOM/CSS поверх canvas** (чистый TS; React — только если станет тесно) | твоя сильная сторона; терминал АРХИВА, инвентарь, тосты — HTML |
| Карты | **Tiled** (JSON) | стандарт, бесплатно, редактируется мышкой |
| Тесты | **Vitest** — только чистые системы (инвентарь/крафт/статы/время) | второй guardrail: ИИ самопроверяется запуском тестов |
| Линт | ESLint + Prettier | единый стиль, меньше пыли в ревью |
| Ассеты | **Kenney.nl** (CC0, topdown-паки) | прототип без художника; иконки по `id` — замена потом без переделки логики |
| Шрифт АРХИВА | Share Tech Mono / JetBrains Mono (Google Fonts) | терминальная эстетика за 0 effort |
| Звук | jsfxr (генерация) + Kenney audio (W6) | сначала вообще без звука |
| Деплой | GitHub Actions → **GitHub Pages** | пуш в main = новая версия по ссылке |
| Сейвы | localStorage (JSON, версия схемы) | |

### Установить (однократно, ~30 минут)
1. Node.js LTS (+ pnpm по желанию).
2. VS Code + ESLint/Prettier расширения (наверняка уже есть).
3. Tiled — с W2 (до этого расставляем сущности кодом).
4. Скачать 1–2 Kenney-пака: «Topdown Shooter», «Generic Items» — в `public/assets/`.

## 4. Архитектура: маппинг UE → Web

Правила AGENTS.md переносятся дословно:
1. **Player худой** — спрайт + input + движение. Логика — в компонентах/системах.
2. **Компонент не знает класс игрока** — только `owner` (минимальный интерфейс сущности).
3. **UI только через события** — DOM подписан на EventBus, никакого опроса из цикла.
4. **Данные в JSON-таблицах** (`src/data/`), не в коде систем.
5. Одна система = одна ответственность; системы включаются/выключаются независимо.

Нейминг: TS-конвенции (классы PascalCase, члены camelCase, файлы kebab-case). UE-префиксы (`BPC_`) НЕ переносим — вместо них таблица маппинга в этом документе (§2).

### Структура папок
```
src/
  main.ts                — bootstrap: конфиг Phaser, монтирование, старт сцен
  core/
    event-bus.ts         — типизированный pub-sub (замена Event Dispatchers)
    game-state.ts        — время, день, coherence, флаги главы
    save-system.ts
  data/                  — «DataTable»-слой: JSON + типы
    types.ts             — S_Item, S_Recipe, S_Effect, E_ItemType, E_StatType...
    items.json  recipes.json  effects.json
    archiv.lines.json    — пулы реплик по minCoherence
    station.modules.json
  scenes/
    boot-scene.ts        — загрузка ассетов
    world-scene.ts       — тайлмап, спавн сущностей, камера, коллизии
  entities/
    player.ts            — ХУДОЙ: спрайт + движение + input
    resource-node.ts     — дерево/руда/мусор (HP, дроп, таймер респауна)
    enemy.ts             — + FSM в components/enemy-brain.ts
    station.ts           — агрегатор модулей
    station-module.ts    — состояние 0..100%, что даёт на 100
    build-spot.ts  projectile.ts
  components/            — компоненты сущностей (аналог BPC_*)
    stats-component.ts         — голод/жажда/HP/выносливость как статы
    inventory-component.ts     — слоты, стак, вес
    conditions-component.ts    — тикирующие баффы/дебаффы
    interact-component.ts      — «что произойдёт по E»
  systems/               — глобальные системы (аналог GameMode-уровня)
    time-system.ts       — день/ночь, расписание событий, N-й день
    crafting-system.ts   — пре-чек материалов, расход, выдача
    wave-director.ts     — цикл атак 3–6 дней, сила от % станции
    archiv-system.ts     — выбор реплик, coherence, глюки
    spawn-director.ts    — респаун ресурсов, спавн врагов ночью
  ui/                    — DOM-слой (только подписки на EventBus)
    hud/  inventory/  crafting/  archiv-terminal/  toasts/  dialogs/
  bridge/
    world-to-dom.ts      — коннект: события мира → DOM
```

### Маппинг поимённо
| UE (GAME_PLAN) | Web |
|---|---|
| BPC_Stats | `StatsComponent` + `E_StatType` |
| BPC_Inventory | `InventoryComponent` + `ui/inventory` |

## 5. Как строится сцена

### Слои рендера (canvas, снизу вверх)
```
1. ground      — тайлмап: бетон, рельсы, грунт (Tiled tileLayer)
2. decor       — тайлмап-декор: трещины, мусор, шпалы
3. entities    — спрайты сущностей, Y-сортировка (игрок за/перед станцией)
4. overhead    — крыши, кроны (опционально, W2+)
5. light-mask  — ночью: тёмный overlay с вырезами-кругами (игрок, костёр,
                 станция после ремонта). Реализация: RenderTexture или шейдер.
```
Камера: follow player (lerp 0.1), bounds = карта. Разрешение 1280×720, `pixelArt: true`, scale FIT.

### Слои DOM (поверх canvas, z-index)
```
z1 hud          — полоски статов, часы дня, прицел, промпт «E — Починить»
z2 archiv       — нижняя лента-терминал: печатающийся текст, CSS-глитчи
z3 panels       — инвентарь (Tab), крафт — оверлей с затемнением, пауза
z4 toasts       — «+2 Металлолом», «Рецепт изучен»
```
Canvas и DOM не пересекаются: DOM получает данные **только** через EventBus.

### Петля кадра
```
update(dt):
  TimeSystem.tick(dt)        → события 'time:dawn' / 'time:dusk' / 'time:newDay'
  StatsComponent.tick(dt)    → голод/жажда тикают от игровых часов, не от кадров
  ConditionsComponent.tick   → дебаффы (голод 0 → «Истощение»)
  EnemyBrain.update(dt)      → FSM
  физика (arcade) + overlaps → события 'combat:hit', 'loot:collected'
  ArchivSystem реагирует на события мира
  → EventBus → DOM-подписчики перерисовывают дельту
```
Логика систем — чистый TS без Phaser-зависимостей где возможно → тестируется Vitest без браузера.

### Управление (десктоп)
- WASD — движение; мышь — направление атаки/прицела; ЛКМ — атака.
- E — взаимодействие; Tab — инвентарь; Q — быстрый слот; Esc — пауза.

## 6. Данные (примеры схем)

`data/items.json`:
```json
{
  "scrap":  { "id": "scrap", "name": "Металлолом", "type": "material", "stack": 50 },
  "copper": { "id": "copper", "name": "Медь", "type": "material", "stack": 50 },
  "part_reactor": { "id": "part_reactor", "name": "Деталь реактора", "type": "stationPart", "stack": 5 }
}
```
`data/recipes.json`:
```json
{ "id": "craft_part_reactor", "cost": { "scrap": 5, "copper": 2 }, "result": { "part_reactor": 1 }, "station": "workbench" }
```
`data/archiv.lines.json` (суть системы «связности»):
```json
{
  "reactor_hint": {
    "text": "Инженер. Реактор станции критически повреждён. Требуется {copper} единиц меди. Ближайший источник — сектор 4-Б.",
    "minCoherence": 0.0, "glitchRate": 0.3
  },
  "gates_done": {
    "text": "Ворота депо функционируют. Периметр... условно безопасен.",
    "minCoherence": 0.34, "glitchRate": 0.05
  }
}
```
`coherence = восстановленный% станции` (3 модуля: реактор 40%, ворота 30%, вышка 30%). Низкая coherence: обрывы фраз, замена слов `...`, повторы. Высокая: чистая речь + карта региона (вышка). Глитч — CSS-анимация + подстановка битых символов.

## 7. Фазы (каждая = шаринг-ссылка с играбельным билдом)

### W0 — Каркас (1 выходной)
Vite+TS+Phaser+ESLint+Vitest, пустая сцена, спрайт ходит WASD, DOM-HUD с часами, GitHub Actions → Pages.
**Выход:** ссылка открывается, персонаж ходит, пуш в main = автодеплой, тесты+typecheck зелёные.

### W1 — Выживание (~1 неделя)
TimeSystem (день 10 мин, ночь = маска света), статы голод/жажда, дебаффы Conditions, ресурсные ноды 3 типов с респауном, инвентарь DOM (стак/тултип/перетаскивание), крафт 4–5 рецептов, смерть → респаун: статы 50% + «Перезагрузка носителя», сейв localStorage.
**Выход:** петля давления времени/ресурса без цели. Играть интересно 10 минут.

### W2 — Станция + АРХИВ (~1–1.5 недели)
Карта депо в Tiled, 3 модуля, починка деталями через E, верстак, ARCHIV v1 (терминал, реплики-подсказки, coherence), финал: 3×100% → свет, гудок, титр станции.
**Выход: ВЕРТИКАЛЬНЫЙ СРЕЗ с началом и концом. → отправить 3 друзьям, собрать фидбек. → CHECKPOINT: решение о судьбе трека.**

### W3 — Враги (~1–1.5 недели)
Melee-атака (дуга по направлению мыши), топор/лом, «Бегун» (wander→alert→chase→attack), «Плевун» (дистанция + снаряд), лут только материалы, ночью агрессия выше (TimeSystem ↔ SpawnDirector).
**Выход:** за ресурсами страшно ходить. Бой простой, но честный.

### W4 — Оборона (~1–2 недели)
WaveDirector: волна каждые 3–6 дней, сила от % станции; урон по модулям (→ чинятся снова); build-spots: турель, шипы; АРХИВ предупреждает за N минут («Датчики фиксируют движение в секторе 7...»).
**Выход:** ритм «днём собирай/строй — ночью отбивайся».

### W5 — Обустройство (по силам, порядок свободный)
Верстак «создай → улучшай» (T2-рецепты), рецепты-находки в мире, кухня (готовка/вода), медотсек, допуски ЖД (предметы-стимуляторы).

### W6 — Полиш
Аудио-проход (jsfxr + Kenney), баланс по фидбеку, минимапа (после вышки — лорно!), PWA/оффлайн, мобайл-тач (stretch), биом №2 (stretch).

## 8. AI-воркфлоу (что меняется против UE-трека)

1. **Я пишу ~весь код, ты ревьюишь как фронтендер** — это и есть проверка гипотезы. Твоя роль: дизайн-решения, ревью, вкус к UI.
2. **Guardrails вместо MCP-магии:** strict TS + ESLint + Vitest. Каждый коммит = зелёные `typecheck` и `test` (перенос правила «компилируемый проект»).
3. **Маленькие шаги:** один PR = одна механика, играбельность не ломается дольше вечера.
4. Данные и баланс правим в JSON — это быстрее, чем в Blueprint вообще когда-либо было.
5. Правила 1–4 из §4 обязательны; я сам их проверяю перед «готово».

## 9. Риски и митигации

| Риск | Митигация |
|---|---|
| Два трека съедают время, ни один не движется | Таймбокс на веб; W2 — жёсткая точка решения |
| Фронтендера тянет полировать UI до геймплея | Правило: UI-полиш только после W2-среза |
| Phaser-специфика (физика, Y-sort, маски света) съест время | Готовые паттерны; если маска света закапывается — упростить до тонирующего overlay без вырезов |
| Ассеты-затык | Kenney CC0 с W0; иконки по id → замена пака = замена папки |
| Баланс/данные разъезжаются с UE-версией | Веб = экспериментальная ветка; источник правды Docs + один формат JSON (потом можно общий датасет двух версий) |
| Выгорание | Каждая W-фаза = ссылка, которую можно показать. Никогда не ломать ссылку надолго |

## 10. Открытые вопросы (решить на W0–W1)

1. DOM-UI: чистый TS (рекомендую) vs React/Preact-слой (если привычнее — допустимо, оверхед мал).
2. Размер тайла: 32px (скорее всего) — зафиксировать по выбранному Kenney-паку.
3. Top-down чистый vs изометрия — рекомендую чистый top-down (проще коллизии и Y-sort).
4. Нужен ли русский/английский сразу — i18n с W1 стоит копейки (JSON-реплики), переделывать потом дороже.
