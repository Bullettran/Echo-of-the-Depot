# План разработки — EchoOfTheDepot

> Принцип: **компонентный подход**. BP_игрок = камера + капсула + input. Вся логика — в ActorComponent'ах.
> Существующие системы из PhaseLands переиспользуем, не переписываем.

---

## Архитектура (целевая)

```
BP_Player (худой: input, камера, капсула)
 ├─ BPC_Stats          (характеристики и нужды: голод/жажда как статы; порт из PhaseLands)
 ├─ BPC_Inventory      (инвентарь; порт, данные+операции)
 ├─ BPC_Crafting       (рецепты, верстак; на базе RemoveCraftingMaterials/CheckExistingRecipes)
 ├─ BPC_Conditions     (слоу/бафы; порт)
 ├─ BPC_Combat         (атака, урон)
 ├─ BPC_Interact       (трейс, взаимодействие)
 └─ BPC_Archiv         (АРХИВ: задачи, реплики, события)

BP_Station (актор станции-депо — статичная база главы; поезд по карте НЕ ездит)
  ├─ BPC_StationModules   (узлы/помещения: состояния 0..100%, починка деталями)
  ├─ BPC_StationDefense   (цикл атак 3-6 дней, волны, урон по модулям)
  └─ BPC_Travel           (переезд-глава: станция 100% → фейд → ролик → Open Level; поезд живёт только в роликах)

BPC_TimeCycle (мировой день/ночь; ГЛОБАЛЬНЫЙ — на GameMode/GameInstance)
BPC_Build (заранее расставленные build-spots: верстак, турель, ловушка)
```

**Правила:**
1. Компонент не знает о BP_Player — только GetOwner() + интерфейсы.
2. UI обновляется через Event Dispatchers, никогда — опросом из Tick.
3. Данные — в DataTable/структурах, не в переменных-блюпринтах.
4. Нейминг: PascalCase везде. Компоненты — `BPC_`, структуры — `S_`, енумы — `E_`, таблицы — `DT_`, интерфейсы — `BPI_`.

## Фаза 0 — Фундамент (3-5 дней)

1. Структура папок: `/Game/Game/{Components,Player,Structures,Enums,Interfaces,Widgets,Data,Docs}`.
2. Скопировать Блок 1+2 из аудита (`MIGRATION_AUDIT.md` в PhaseLands): енумы, структуры, DT, Icons, Items, BPC_Inventory, BPC_Stats+BPI_Combat.
3. Проверить компиляцию, порвать ссылки на BP_Player (LootComponent — на потом, не копировать в Фазе 0).
4. Переименовать `BP_ThirdPersonCharacter` → `BP_Player`; input-маппинги оставить.
5. Настроить GameMode: свой спавн, худой плеер.

**Выход:** проект компилится, игрок ходит, ассеты данных на месте без ошибок.

## Фаза 1 — Выживание и АРХИВ (2-3 недели)

*(Решение 20.10: Фазы 1 и 2 поменяны местами — сначала выживание/АРХИВ на примитивах, станция следом. Причина: не задерживаться на ассетах.)*

1. `BPC_TimeCycle`: день = 10 минут реального времени, счётчик дней, события по расписанию.
2. Нужды — в `BPC_Stats` (решение 21.10: отдельный BPC_SurvivalNeeds убран — модель та же, дублирование). Голод/жажда — статы; пороги значений → дебаффы через `BPC_Conditions`; холод/жара — тоже Conditions (среда, без полосок — иконки с 3 состояниями). Открытый вопрос к реализации: источник тика голода/жажды (события BPC_TimeCycle или таймер) — решить при имплементации.
3. Источники: еда (собрать/приготовить), костёр/обогреватель (временный актор-заглушка, полноценные build-spots — Ф5), жара днём в пустоши.
4. `BPC_Archiv` v1: DT_реплик + подсказки задач + тосты-субтитры; уровень «связности» v1 — по выполненным задачам/дням выживания (привязать к % станции, когда появится она в Ф2).
5. Смерть: респаун в точке спавна (позже — у депо). **Решение 21.10: потеря инвентаря ОТМЕНЕНА** (лут = мотивация игрока; решение за автором). Последствия смерти: статы на 50% (`RestartBeginStats(Half)`) + план: дебафф «Перезагрузка носителя» через BPC_Conditions (гасит эксплойт «умереть = телепорт домой»).

**Выход:** петля с давлением времени и ресурса. АРХИВ ведёт игрока.

## Фаза 2 — Вертикальный срез ядра: станция (2-3 недели)

Цель: **собрал → скрафтил → починил станцию → станция ожила**.

*(Решение 20.10: поезд заменён стацией — движущегося поезда в игре нет, переезд = ролик. Причина: цена движущейся базы для соло-дева неприемлема.)*

**Уже готово (20.10):** инвентарь + UI, крафт с пре-чеком материалов, ресурсы (BP_Resource, топор, разрушаемая геометрия, респаун), взаимодействие (BPI_Interact), HUD + тосты.

**Осталось:**
1. `BP_Station`: актор станции-депо + 3 узла-заглушки (реакторная, ворота депо, сигнальная вышка) — пока на примитивах.
2. `BPC_StationModules`: узлы 0→100% через крафтовые детали; взаимодействие «починить» через BPI_Interact.
3. 5 рецептов деталей станции в DT_Items + верстак в мастерской (точка размещения крафта).
4. **Финал среза:** все узлы 100% → станция оживает (свет, ворота, гудок) → фейд + титр **с названием станции** (решение 21.10: без концепта «глав» — survival показывает место, а не номер главы). Видео-ролик — НЕ в Ф2 (Ф6).
5. Расставить ресурсы 3 типа (металлолом, медь, топливо) вокруг станции + респаун через BPC_ActorSpawner.
6. Связать «связность» АРХИВА из Ф1 с % восстановления станции.

**Выход:** играбельная петля без врагов. Показать другу: понятно ли без слов.

> Статус Ф2 (решение 24.10): механика станции готова (модули/крафт/агрегатор/финал). Ресурсы вокруг станции (шаг 4) и АРХИВ↔станция Coherence (шаг 5) — **перенесены к работе над локацией**. Приоритет смещён на оружие: **стрельба из пистолета (тянем из Ф3-Ф4 вперёд по запросу автора)**.

## Фаза 3 — Враги и лут (2-3 недели)

1. 2 типа врагов на BT: «Бегун» (melee rusher), «Плевун» (ranged). Шлейф-визуал.
2. `BPC_Combat` игрока: melee-атака (анимации уже есть), уклонение.
3. Лут: **только материалы** (лом, ткань, кишки-проводники). Никакого готового оружия из врагов.
4. `BPC_LootComponent` (перепривязанный) + рюкзак-лимит через Overburdened.

**Выход:** за ресурсами страшно ходить; бой простой, но честный.

## Фаза 4 — Оборона станции (2-3 недели)

1. `BPC_StationDefense`: таймер 3-6 дней → волны к станции; мутанты чуют реактор.
2. Урон по модулям: помещения станции получают % повреждений → чинятся материалами.
3. Ловушки/турели: build-spots вокруг станции; 2-3 blueprint'а (шипы, самопал-турель).
4. Волны через `BPC_TimeCycle` события; АРХИВ предупреждает за N минут.

**Выход:** ритм «собирай/строй днём — отбивайся в цикл атаки».

## Фаза 5 — Стройка и помещения станции (2 недели)

1. `BPC_Build`: заранее расставленные build-spots (верстак у мастерской, костёр, турельные гнёзда).
2. Оживить помещения станции: кухня/столовая (готовка), медпункт (лечение), склад (общий инвентарь). *(Решение 21.10, LORE разд. 6: станции-крафта стало больше.)*
3. **Верстак по схеме «создай → улучшай»**: build-spot → построить верстак → уровни верстака открывают T2-рецепты; рецепты — находимые предметы (принос на верстак → изучение).
4. Дополнительные станции (после ядра Ф2, по мере сил — хобби-проект, порядок свободный): **горн** (металл T2, модификации оружия: яд/кровотечение), **водокачка** (фильтрация воды), **радиорубка** (апгрейды АРХИВА, потом Ф4-предупреждения).
5. **Допуски ЖД вместо XP** (LORE разд. 6): лаборатория синтезирует допуски (скорость/HP/голод-вместимость/броня) — предметы-стимуляторы, не система опыта.

## Фаза 6 — Глава 2: биом (3+ недели)

1. `BPC_Travel` v2: фейд + титр из Ф1 заменить на AI-видео/слайды переезда (10-30 сек, из Content/Movies) + Open Level.
2. Новый биом: топи/мёртвый лес — новая станция-узел, новые ресурсы, погода (холод), враг-вариация.
3. Сохранение: `BP_Save` — станция, инвентарь, время, постройки.

## Риски и как гасим

| Риск | Митигация |
|---|---|
| Раздувание BP_Player | Правило №1 архитектуры; ревью после каждой фазы |
| Станция-«фича-монстр» (модулей хочется больше, чем нужно) | Вертикальный срез Фазы 1 на 3 узлах до любых украшений; новый модуль = только если несёт механику |
| «Станция готова» — критерий размыт | Готовность = 3 ключевых узла на 100%, зафиксировано в плане |
| Анимации/модели съедят время | Контент только под вертикальный срез |
| Выгорание соло | Каждая фаза = играбельный билд. Никогда не ломать билд надолго |
