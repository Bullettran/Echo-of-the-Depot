# USEFUL — хранилище хороших идей

> Сюда агент записывает удачные находки, дизайн-решения и приёмы, чтобы они не потерялись.
> Идея может «созреть» здесь месяцами, прежде чем попадёт в GAME_PLAN. Это норма.

---

## Лор и нарратив

- **Связность АРХИВА = прогресс станции.** Чем больше узлов станции восстановлено, тем связнее говорит АРХИВ (меньше глюков). Лор становится метрикой прогресса — бесплатно.
- **Тосты в стиле «архивных записей»**: зерно, помехи, «ЗАПИСЬ КАМЕРЫ 7-Б». ИИ-генерация стилизованных кадров стабильнее реалистичных.
- **Переезды = главы.** Ролик-переход → титр («Глава 2: Топи») → новый биом. Кинематографично и дёшево.
- **Валюта: «Жетоны Гелиоса»** (фаворит) или «Киловатты». Деньги = остатки того, что убило мир. Из врагов валюта НЕ падает (только материалы) — заработок через сдачу ресурсов/задания. В коде уже есть `PickupTokens`.
- **Аномалии шлейфа = richest ресурсы.** Чем опаснее зона — тем ценнее материалы. Готовый risk/reward.

## Геймдизайн

- **Поезд не ездит по-настоящему — `BPC_Travel`.** Переход = фейд → слайды/AI-видео → Open Level. Настоящая езда по сплайну — опциональный апгрейд Ф6, внутренности компонента заменимы без касания вызывающих. Ролик маскирует загрузку уровня.
- **Стройка = заранее расставленные build-spots.** Верстак и турели стоят в запланированных местах, игрок не двигает их. Экономит недели.
- **Температура — одна ось** (Warmth), а не две нужды «холод» и «жара». Холодная ночь тянет вниз, пустошь днём — вверх, края = Freezing/Overheating через Conditions.
- **Из врагов падают только материалы**, никогда готовое оружие. Крафт остаётся центром экономики.

## Техника (паттерны, которые прижились в проекте)

- **Радио-схема:** компонент Broadcast → UI слушает. Компонент никогда не ищет виджеты; виджет находит компонент через `GetOwningPlayerPawn → GetComponentByClass → IsValid`.
- **Пayload вместо количества диспетчеров:** `OnInventoryChanged(ChangeType, Item, Count)` лучше четырёх событий «picked/removed/...». Диспетчер = завершение пользовательского действия, не каждый внутренний чих.
- **Каждый GetComponentByClass = IsValid + внятный Warning-лог.** Тихий None = тихо неправильная игра.
- **FindItemCount переиспользуется** везде, где нужно «сколько имеем» (крафт, UI материалов, тосты).
- **bSilent-параметр** у мутаторов (RemoveItem) — служебные вызовы не спамят события.
- **Стройка без перемещения** — запланированные точки вместо free-build.
- **Рецепты живут в строках предметов** (S_Craft внутри DT_Items) — не отдельная таблица, меньше рассинхрона.
- **ZOrder-шкала для viewport:** HUD = 0, окна интерфейса = 10, тосты/уведомления = 100. Тосты добавлять собственным `AddToViewport(100)`, а не внутрь HUD-канваса — ребёнок не может подняться выше родителя среди viewport-детей.
- **NiagaraToolsets есть в движке 5.8** (Epic, Experimental, `Engine\Plugins\Experimental\Toolsets\NiagaraToolsets`): 35+ tool calls (системы/эмиттеры/модули, BP-врезка компонентов, user-параметры) + 7 Agent Skills (fundamentals/renderers/custom_hlsl/…). EnabledByDefault=false — включать в .uproject при закрытом редакторе (`{"Name":"NiagaraToolsets","Enabled":true}`). После перезапуска появляется в MCP. Проверять наличие engine-плагинов не по list_toolsets (показывает только подключённые), а по папке Experimental\Toolsets в движке.
- **read_graph_dsl — только карта, не приговор.** Систематически врёт: (а) роняет exec-выходы EnhancedInputAction/InputKey (события выглядят пустыми — BP_Player IA_Move «пустой», а работает); (б) переворачивает условие if и порядок веток (`>=` показывает как `not(>=)`, else как продолжение then); (в) у Array Get показывает подключённый индекс отсутствующим, а литерал 0 — как подключение (ChangeStats: читатель «показал» индекс там, где стоит литерал 0, и наоборот); (г) дорисовывает литерал 0 у сравнения `>`, когда второй операнд по пинам ПУСТ (BPC_Combat.Shoot, 01.11 — «CurrentAmmo > 0» выглядело рабочим, а пин висел в воздухе). Вердикт «пусто/баг/цикл» — только после `get_node_infos` по exec/data-пинам. Пакетная проверка графов: find_nodes(title) → get_node_infos(nodes=[...]) с печатью exec-связей.
- **MCP-раннер mcp.ps1 съедает массивы**: returnValue-массив (list_graphs/find_nodes) разворачивается в пробелы — для таких инструментов дёргать MCP напрямую сырым JSON-RPC (сниппет в истории сессий 01.11) или чинить раннер.
- **read_graph_dsl вставляет фантомные узлы в AnimBP EventGraph** (кейс A_ABP_Unarmed, 02.11: рисовался несуществующий `(ToolMenus|Get)` между реальными statement'ами). Для AnimBP-графов — только find_nodes + get_node_infos по пинам. там же: readback рендерит вызов своей функции как `(NodeType arg1 arg2)` с позиционной формой — при ОБРАТНОЙ записи обязательно keyword `:PinName`.

## Анти-паттерны (замечено и избегается)

- God-class BP_Player со всей логикой — причина боли миграции в старом проекте.
- Логика в виджетах → умирает при переделке UI, не тестируется, не переиспользуется.
- `CastToBP_Player` в виджетах — привязывает UI к классу; заменено на GetComponentByClass.
- Мерж-конфликты в бинарных ассетах — решены Perforce exclusive checkout (binary+l).
